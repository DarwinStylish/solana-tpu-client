# 1. Fixed-Layout Trade-Event Parser Prototype

Date: 2026-07-12

## Status

Accepted for the current prototype.

## Context

The current ingress prototype consumes a project-specific fixed-layout trade-event payload derived from a local schema used by the HFT research stack.

This payload must not be confused with the Solana TPU transaction-ingress protocol or with a general-purpose Borsh decoder.

The parser exists to evaluate a low-overhead translation path from a known binary event layout into the engine `event_t` representation.

## Decision

The prototype uses generated byte offsets for the fields required by the engine:

- timestamp;
- price;
- quantity;
- side.

The parser validates that the input buffer is at least the expected schema size, reads the selected fields, and writes them into a preallocated output structure without heap allocation.

The generated offsets are derived from the local schema used by the prototype. Schema generation does not make the parser a general Solana or general Borsh implementation.

## Consequences

### Positive

- no heap allocation occurs in the parser path;
- the implementation is small and straightforward to microbenchmark;
- schema offsets can be regenerated when the prototype schema changes.

### Limitations

- the decoder is tightly coupled to one fixed event layout;
- it does not parse Solana transactions;
- it does not implement TPU networking;
- it does not validate that input originated from a Solana validator or on-chain program;
- current direct integer loads require separate portability review for alignment and byte-order behavior.

A future TPU transaction-delivery implementation is a separate transport concern and does not depend on this event-parser design.
