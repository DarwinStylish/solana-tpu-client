# Current Implementation Status

## Purpose

The repository name reflects the intended Solana TPU transaction-delivery project. The current codebase is an earlier ingress/parser prototype and must not be interpreted as a complete TPU client.

## Implemented

The current revision implements:

- a non-blocking UDP socket bound to a caller-provided local port;
- reception of fixed-layout trade-event datagrams;
- translation of selected fields into the private engine `event_t` structure;
- an SPSC queue handoff into the private engine;
- localhost UDP integration testing;
- a synthetic parser-and-queue microbenchmark.

No heap allocation occurs inside the current parser or SPSC queue operations.

## Current Coupling

The public repository currently includes headers from `../../engine/private/include`.

That private dependency supplies:

- `event_t` and associated venue/event definitions;
- the current fixed-layout parser interface;
- generated parser offsets;
- the SPSC ring buffer.

The current repository therefore cannot be considered a standalone public TPU transport library.

## Not Implemented

The current revision does not implement:

- Solana TPU transaction submission;
- QUIC client transport;
- TLS identity handling;
- `solana-tpu` ALPN negotiation;
- leader schedule tracking;
- TPU contact-information resolution;
- connection pooling;
- connection prewarming;
- stake-weighted QoS behavior;
- transaction routing or leader fanout;
- retry and backpressure policies;
- landing or confirmation observation;
- Agave/Firedancer TPU-ingress conformance;
- kernel-bypass networking.

## Parser Scope

The current decoder operates on a project-specific fixed-layout trade-event schema. It is not a general Solana transaction decoder, a general Borsh implementation, or the Solana TPU wire protocol.

The sequence identifier currently attached to parsed events is generated by the local receiver. It is not an exchange- or validator-assigned sequence number.

## Benchmark Scope

The current benchmark repeatedly decodes one preallocated synthetic payload and performs an enqueue/dequeue round trip on the same thread.

It does not measure:

- socket receive latency;
- QUIC transport;
- cross-core queue transfer;
- validator processing;
- transaction propagation;
- transaction landing;
- end-to-end submission latency.

Reported timings must therefore be interpreted only as synthetic local parser-and-queue microbenchmark results.

## Target Boundary

The intended public transport boundary is:

1. accept an opaque signed serialized Solana transaction;
2. obtain current cluster routing information through a discovery provider;
3. select and maintain appropriate TPU ingress connections;
4. submit the transaction through the supported TPU transport;
5. expose structured delivery status and telemetry.

Transaction construction, signing, trading strategy, portfolio state, and private execution-engine behavior remain outside the transport library.
